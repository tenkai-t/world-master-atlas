## 2. WindowsでGitHubへ登録

1. ZIPをWindowsで「すべて展開」する。
2. 展開された `world-master` の中にREADME.md、package.json、public、app等があることを確認。
3. GitHub Desktopで世界マスター用の空のローカルリポジトリを用意する。漢字クラッシュなど別ゲームのリポジトリへ混ぜない。
4. そのリポジトリ直下へ、`world-master` の**中身**をコピーする。publicだけでなく、`.openai`、`.gitignore`、ロックファイル等も含める。`.git`はZIPに含まないので、Desktopが作ったものを保持する。
5. GitHub Desktopの変更一覧を確認し、初回コミットしてGitHubへ送信する。リポジトリはまずPrivateを推奨。
6. GitHub上でpackage.json・README.md・public等が直下に見えることを確認する。

ZIPそのものをリポジトリに登録しても、Codexがプロジェクトとしてそのまま扱えるわけではありません。**展開後のファイル一式を登録してください。** 全部をブラウザでアップロードするより、GitHub Desktopで送る手順が扱いやすいです。今回こちらからGitHubへの登録・pushはしていません。

## 4. 既存データはどこにあるか

| 保存対象 | 場所 | コードのZIPで移るか |
|---|---|---|
| 名前・アイコン・安定ローカルID | 各利用端末のlocalStorage | 移らない。保存形式とキーをコードで保持 |
| 本人/先生のPIN保護・ロック設定 | 各利用端末の保護用localStorage | 移らない。学習バックアップに含まれない |
| 回答数・正答率・履歴・復習・自己ベスト・勲章等の学習情報 | 各利用端末の個人学習データ | 移らない。既存バックアップ互換処理は同梱 |
| 公式挑戦の途中・再送待ち | 端末のsessionStorageとD1の挑戦テーブル | 移らない |
| オンラインID・操作鍵・名前変更の送信待ち | 端末の専用localStorage | 移らない。学習バックアップに含めない |
| 新旧オンラインランキング・サーバー採点・オンラインプロフィール | Sites管理D1 | 実データは移らない。スキーマとサーバーコードだけ同梱 |
| PWA教材パック | ブラウザのCache Storage | キャッシュ自体は移らない。元の教材・SW・マニフェストを同梱 |

**GitHubへコードを登録しても、現在のサイト・端末内データ・本番DBはそのまま残ります。** 別ドメイン、別ポート、別ブラウザ、別端末では別オリジンの保存領域になり、自動で同じ記録は見えません。

現行の学習バックアップは、読み込むと新しいプレイヤーとして追加します。元のローカルID・PIN・先生設定・オンラインの本人情報を丸ごと複製する形式ではありません。同じオンライン成績を継続するには、元の端末情報と同じSitesアカウントが必要です。別端末/別オリジンへID・保護設定も含めて移す作業は、別途の明示的な移行設計が必要で、今回実行も新機能追加もしていません。

## 5. オンラインDBと接続設定の調査

本番のDBメタデータだけを確認しました。データ行は一切読み取っていません。

- 管理：既存SitesのCloudflare D1、論理バインディング `DB`。
- `.openai/hosting.json` は既存Siteのproject_id、`d1: "DB"`、`r2: null`。project_idは接続資格情報ではありません。
- `app/api/rank/[action]/route.ts` が `cloudflare:workers` のenv.DBを受け取り、サーバー処理に渡す。
- `db/schema.ts` と `drizzle/` がスキーマと移行履歴。
- 通常のブラウザ学習データ全体をD1へ保存する設計ではない。
- 本番DBのCloudflare account_id、実database_id、APIトークンは取得ソースにはなく、今回取得していない。
- vite.config.ts/ローカルビルドにある全0のdatabase_idはローカル用プレースホルダー。本番接続先と解釈しない。

本番メタデータで確認したテーブル：

| テーブル | 用途 |
|---|---|
| ranking_players | 不変オンラインID、認証アカウントとの関連、操作鍵ハッシュ、名前・アイコン、プロフィール更新制御 |
| player_ranking_runs | 新プレイヤー別の出題・回答・開始/終了・採点 |
| player_ranking_scores | 新プレイヤー別の部門・条件別自己ベスト |
| ranking_runs | 旧アカウント単位の挑戦記録 |
| ranking_scores | 旧アカウント単位の部門・条件別成績 |

氏名やID等の実値は調査・表示していません。オンライン操作鍵はサーバーではハッシュを保存し、端末の平文操作鍵と照合します。Sitesの信頼できる認証境界が `oai-authenticated-user-id` を付ける前提です。一般のホスティング先で単に同名ヘッダーを信用すると他人になりすませるので、Sites外へ公開する際は別途適切な認証を実装しなければなりません。

## 6. DBのバックアップ方法：今回の結論

**この作業で利用できるSites管理機能には、DBのバインディング/テーブル一覧と行のページ閲覧がありますが、正式な全体SQLエクスポート操作は見当たりませんでした。行の閲覧を繰り返してDBバックアップを代用していません。** ソースリポジトリの資格情報はDBの管理権限ではなく、ZIPから本番DBへ接続できるとは言えません。

Cloudflare D1自体には、権限を持つ管理者向けのSQL exportとTime Travelがあります。ただしSitesが管理するこのDBで、利用者がそれらの操作権限・DB ID・保持期間を取得できるかは未確認です。Cloudflareの一般機能があることを、このSitesで直ちに実行できるという意味にはしません。

将来、管理元が正式に許可した場合のコマンドの形だけを示します（**今回は未実行**）：

```text
wrangler d1 export <管理元が指定した実DB名> --remote --output=<Git管理外の安全な保存先>/database.sql
```

exportは実データを取得する作業です。実施には改めて許可・管理権限・保管方法の確認が必要です。実行中に通常のDBリクエストを妨げる場合があるため、管理元へ影響も確認します。Time TravelはDB復旧の機能で、移行用のSQL取得と同じではありません。復元は本番状態を書き換えるため今回の範囲外です。

正式手段が提供されるかは、OpenAIのサポート窓口または組織のSites管理者に、次を添えて確認してください。今回問い合わせの送信はしていません。

- 対象Site名とURL、所有者であること、論理DBバインディングDB
- 目的はCodexへの引き継ぎ準備、ソースとDB移行を分離していること
- スキーマ・全テーブル・インデックス・移行履歴を含む整合したSQLバックアップを、元データを変更せず取得する正式手段の有無
- export/Time Travelの利用権限、バックアップ保持期間、取得に伴う稼働影響、暗号化された受け渡し方法
- 元のアカウント識別子を新しいSite/別ホストへ引き継げるか（移行前提を確認）

参考（2026-10-26に確認）：
- Sitesの概要：https://learn.chatgpt.com/docs/sites
- D1 SQL export：https://developers.cloudflare.com/d1/best-practices/import-export-data/
- D1 Time Travel：https://developers.cloudflare.com/d1/reference/time-travel/

## 7. ZIPに含む/含まないもの

含む：最新のHTML/CSS/JS、画像・写真・SVG国旗、地図・世界遺産・首都・ヒントJSON、フォント、かな/漢字モデル、SW、マニフェスト、依存定義・ロック、サーバーコード、DBスキーマ、移行SQL、ライセンス、人工データを使うテスト、引き継ぎ資料。

含めない：node_modules、ビルド生成物dist、Git履歴・Git認証設定、環境変数ファイル、Cookie、トークン、APIキー、秘密鍵、本番/ローカルDBファイル、実ユーザーの学習バックアップ、PIN/復旧コード/操作鍵の実値、作業用ランタイム状態。

テスト内のサンプルPIN・サンプル名・ランダム生成IDは人工データであり、実プレイヤーの認証情報ではありません。これらを本番に転用しないでください。
